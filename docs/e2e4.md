# Search after e2e4 with 128 and 4,096 nodes

After `e2e4`, how much search does Black need to choose a reply? The Classic example plays White’s move, copies the position, searches the copy, and applies the published reply to the live game. Keep the position and the three-ply depth limit fixed. Change only the number of nodes the search may visit. [Runnable example](../examples/classic.cpp#L10-L60)

From the Litch-Max root, use CMake 3.20 or newer with C11 and C++17 compilers.

```sh
cmake -S . -B build/examples -DCMAKE_BUILD_TYPE=Release \
  -DBUILD_TESTING=OFF -DLITCH_MAX_BUILD_EXAMPLES=ON
cmake --build build/examples --target example_classic --parallel 2
./build/examples/example_classic
```

The checked-in example sets `config.maxNodes = 4096;`. For the second run, change that line to `config.maxNodes = 128;`, then rebuild and run the example again. [Search configuration](../examples/classic.cpp#L24-L29)

```sh
cmake --build build/examples --target example_classic --parallel 2
./build/examples/example_classic
```

| Node limit | Nodes visited | Completed depth | Black’s reply |
| ---: | ---: | ---: | --- |
| 128 | 128 | 2 plies | `b8c6` |
| 4,096 | 734 | 3 plies | `b8c6` |

A ply is one move by one side. At 128 nodes, the engine finished two plies and began a third. When its budget expired, it could still publish the reply from the last completed depth. At 4,096 nodes it reached the requested depth after 734 visits. Both runs moved Black’s knight from b8 to c6. The depth and interruption flag tell you what changed even when the chosen move stays the same.
